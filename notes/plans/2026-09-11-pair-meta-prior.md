# Pair-Aware Meta Prior — implementation plan (2026-09-11)

Status: implemented 2026-09-11 (branch `pair-prior`, merged to main as
42265fa). Deviations: none. Golden rows moved: none.

**Goal:** Let observed weapon PAIRINGS from the killer-party harvest enter scoring through the meta prior (the 0.15 `delta` slot) — `meta(w, party) = (1-λ)·solo(w) + λ·best-partner(w, party)`, λ = 0.5 — with the artifact derived on the training split, org-gated, shrunk, and never a penalty.

**Architecture:** `derive_meta_prior.py` grows a second table (`meta_pairs`) in the same `out/meta_prior.json`; `build_dataset.py` validates and attaches it as `scoring.meta_pairs` and the blend weight `weights.meta_pair` comes from `templates/scoring.yaml`; both engine twins read it in `meta_of` / `metaOf`, `comp_score` and `_pick_tail`, keeping the pick score an exact `comp_score` delta; the dashboard only translates three new descriptive fields.

**Tech stack:** Python 3 (`py -3`), Node (engine twin + parity), script-style tests (not pytest), `jsonfmt` for artifacts.

**Spec:** `notes/specs/2026-09-11-pair-meta-prior-design.md`

### Task 1: Derivation — `meta_pairs` on the training split — done

- Files: `pipeline/derive_meta_prior.py` (whole file; ~120 lines before); create `tests/test_meta_pairs.py`.
- Interfaces: `derive(doc, k=8.0, min_prior=0.05, holdout_mod=5, log_cap=3.0, min_pair_parties=5, min_pair_orgs=3) -> dict` with keys `meta_prior` (unchanged shape `{bucket: {weapon: float}}`), `players`, `meta_pairs` (`{bucket: {weapon: {partner: float}}}`, symmetric), `pairs_n` (`{bucket: {"A|B": int}}`, A < B), `_split` (`{"holdout_mod": int|None, "rule": str}`), `_pair_params`. `pair_score(n_ab, n_a, n_b, n_total, k, log_cap) -> float` (pure, testable). `in_split(battle, holdout_mod)` — training-split membership. `bucket_of(party_size)` unchanged (golden T46 pins it).
- Derivation: solo — distinct players per weapon per bucket (R27), training split only. Pairs — one PARTY, one vote per distinct pair it fields (`sorted(set(weapons))`, `itertools.combinations`); org votes from the party's sorted guild tuple (an unknown guild-set casts no ORG vote); a pair carries a row only with >= `min_pair_parties` parties and >= `min_pair_orgs` distinct guild-sets; `s = clamp(log2 lift, 0, log_cap)/log_cap * n/(n+k)` rounded to 3 places, omitted under `min_prior`; rows written symmetrically. The artifact records `_unit`, `_pair_unit`, `_bucket_rule`, `_split`, `_k`, `_min_prior`, `_pair_params`. `main()` takes `--all-battles` (audit copy `out/meta_prior-all-battles.json`, gitignored, never shipped) and prints per bucket the top three weapons and the top three pairs plus the split rule.
- Contracts, Part A (synthetic mid-bucket doc: pair A+B fielded by 6 parties across 4 guilds on training battles; C+D by 6 parties but ONE guild; E+F only on holdout battles; A+A duplicates in one party; X+Y in every party): A1 `_split` records the holdout rule; A2 A+B carries a row (6 parties, 4 guilds); A3 the map is symmetric; A4 C+D omitted (one guild fails the >=3 org gate); A5 E+F omitted (only on holdout battles); A6 no self-pair from the A,A party; A7 X+Y omitted (lift 1 is neutral, never a penalty); A8 pair score = clamp(log2 lift,0,3)/3 * n/(n+K) on the hand case (N=18 training parties, n_A = 12, n_B = 6, n_AB = 6 → lift 1.5); A9 `pair_score` is 0 at lift <= 1 and saturates at 8x; A10 the solo prior ignores holdout battles too; A11 `--all-battles` derivation includes E+F and records the split as None; A12 `_pair_params` recorded; A13 every pair value in (0, 1].
